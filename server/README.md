# Подключение профилей к серверу Material Chat

`profile_api.py` — дополнение к серверу из репозитория `material-caht`. Сам сервер в том репозитории не изменён автоматически. Пока дополнение не установлено и не развёрнуто на Render, новые профили не сохраняются и не видны другим. Существующий вход и регистрация продолжают использовать старый API.

## Установка

1. Скопируйте файл `profile_api.py` в корень серверного репозитория рядом с `main.py`.
2. В начале `main.py`, рядом с остальными импортами, добавьте:

   ```python
   from profile_api import install_profile_api
   ```

3. Найдите строку `tg_codes = {}` и сразу после неё добавьте:

   ```python
   install_profile_api(app, SessionLocal, engine, UserDB, tg_codes)
   ```

   На этом месте `app`, `SessionLocal`, `engine` и класс `UserDB` уже определены. Дополнение создаст отдельную таблицу `chat_profiles` в существующей базе. Дополнительные зависимости не требуются.
4. Сохраните серверный репозиторий и дождитесь успешного деплоя на Render. Затем обновите `manager.html` из ветки этого репозитория. При действующей сессии профиль редактируется без дополнительного запроса пароля. После истечения сессии нужно войти заново обычным способом. Если сервер перезапустился, вход в профиль тоже потребуется повторить: временные сессии живут в памяти процесса до 12 часов.

Сохранённые ник, необязательный уникальный юзернейм и аватарка отображаются в глобальном чате. Старые сообщения используют строковый `sender`: если она совпадает с идентификаторами нескольких аккаунтов, профиль намеренно не подставляется. Клиент обновляет данные авторов примерно раз в минуту; изменение может появиться у других не мгновенно.

## Важно до публичного запуска

Это расширение **не исправляет безопасность старого сервера**. В исходном сервере пароли хранятся открытым текстом, старый `/api/auth` может создавать аккаунты без проверки кода, а отправка сообщений не привязана к проверенной сессии. Поэтому отправителя сообщения можно подделать, и наличие ника/аватарки не доказывает личность. В интерфейсе имя Telegram по умолчанию не показывается, но старый API всё ещё передаёт идентификатор отправителя в данных сообщений.

В серверном репозитории также был опубликован токен Telegram-бота. Отзовите его в BotFather и настройте новый через переменные окружения, не добавляя его в Git. Не размещайте публичный продукт с этими ограничениями: нужны безопасное хранение паролей, обязательная проверка кода, ограничение попыток входа, авторизация сообщений и защита профилей.

Существующий сервер использует SQLite-файл в рабочем каталоге. На Render без постоянного диска данные могут пропасть после пересоздания сервиса: это относится и к аккаунтам, и к профилям. Настройте постоянное хранилище и резервные копии до использования реальными людьми.
