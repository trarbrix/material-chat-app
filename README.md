# Material Chat

Весь интерфейс, JavaScript и каталог эмодзи находятся в одном файле `manager.html`: его можно целиком скопировать для проверки. Откройте `manager.html` через статический веб-сервер, например `python3 -m http.server 8000`, затем перейдите на `http://localhost:8000/manager.html`. Для входа и сообщений используется API: при открытии файла и на localhost — существующий `https://material-caht.onrender.com/api`, а на других хостах — `/api` того же сайта. Развёрнутого сервера API в этом репозитории нет; `server/` содержит только необязательное дополнение к отдельному серверу.

## Возможности

- Русский, английский, немецкий, украинский и французский языки; язык доступен также на экране входа.
- На телефоне список чатов, переписка и настройки открываются отдельными экранами; правила раскладки для ПК не заменяются.
- Вход и регистрация сохраняют интерфейс из предоставленного варианта `manager (1).html`. При ошибке отправки серверного кода клиент не придумывает код и не выполняет вход.
- Темы, анимации и параметры полей сохраняются в браузере. Энергосбережение отключает анимации, проверяет сообщения раз в 30 секунд; в обычном режиме — раз в 15 секунд. Опрос приостанавливается в скрытой вкладке, а при ошибках интервалы увеличиваются до двух минут.
- Профили с ником, необязательным юзернеймом и аватаром требуют установки серверного дополнения: см. `server/README.md`. В глобальном чате показываются публичные данные автора. До установки дополнения они не сохраняются на сервере.
- Дополнительные темы и настройки реакций перенесены из предоставленного варианта. Для обмена реакциями между пользователями сервер должен поддерживать `/api/reactions`; существующий старый сервер может не поддерживать этот маршрут. Дополнительные аккаунты требуют соответствующего серверного `/api/accounts` и авторизованной сессии.
- Настройка установки приложения показывает возможность установки только при поддержке браузера. Одного HTML-файла недостаточно для офлайн-PWA: для установки нужны дополнительные ресурсы и конфигурация сайта.
- Папки создаются кнопкой `+ / ⚙` над списком чатов или в настройках. Выберите чаты в папке; её можно переименовать или удалить без удаления чатов. Папки хранятся в localStorage отдельно для каждого имени пользователя на текущем устройстве.
- ИИ-помощник — отдельный локальный чат. В настройках чата укажите HTTPS-адрес OpenAI-совместимого `/chat/completions`, название модели и при необходимости ключ. Провайдер должен разрешать CORS-запросы из браузера; его использование может быть платным. Запросы и последние сообщения истории отправляются выбранному провайдеру. История хранится в localStorage по имени пользователя, ключ — только в памяти до перезагрузки страницы. Без настройки провайдера ответы не генерируются.
- При неудачной отправке сообщения интерфейс показывает HTTP-код или ошибку соединения и возвращает текст в поле ввода.
- Панель эмодзи в чате содержит категории и поиск по английским названиям, в том числе варианты оттенков кожи. Доступность конкретных символов зависит от устройства и шрифтов. Стикеры пока не реализованы.
- Параметры приватности скрывают имя и размывают сообщения **только на этом устройстве** (сообщения можно показать наведением или фокусом). Они не ограничивают доступ других пользователей и не обеспечивают шифрование. Настройки и папки не синхронизируются между устройствами.

Внимание: для настоящей приватности необходимы авторизация, проверка прав доступа и, при необходимости, шифрование на сервере. Их нельзя обеспечить настройками интерфейса; проверить или изменить сервер в этом репозитории невозможно.

## Проверки

`npm ci && npm test` запускает тесты интерфейса в jsdom с имитацией API. Это не проверка работы реального сервера или входа.

Данные эмодзи: unicode-emoji-json и emoji-datasource; лицензии находятся в `assets/`.

Также обратите внимание: новый серверный маршрут регистрации проверяет Telegram-код, но старый серверный `/api/auth` по-прежнему позволяет обходить эту проверку. До публичного запуска необходимо устранить существующие проблемы авторизации, перечисленные в `server/README.md`.

Обновление `manager.html` само по себе не обновляет уже установленный APK: приложение необходимо пересобрать с новым HTML. При открытии HTML через `file://` запросы к серверу могут быть заблокированы Cloudflare/CORS; это изменение не устраняет эту серверную проблему.

## Вариант B

`variant-b.html` — самостоятельный новый интерфейс из присланного варианта B; прежний `manager.html` сохранён без замены. Вариант B включает отдельные мобильные экраны, прежние окна входа и регистрации, настройки языка, тем, папок, приватности и энергосбережения, эмодзи и отдельный настраиваемый чат с ИИ. Локальные папки и настройки не являются серверной защитой данных. Форма аватара сохраняется только в браузере.

Настройки варианта B разделены на пункты. В разделе «Темы и обои» можно выбрать узор, убрать фон или загрузить PNG, JPEG или WebP до 8 МБ; изображение уменьшается и хранится только в браузере на этом устройстве. Оно не отправляется на сервер и не видно собеседникам.

Вход и регистрация обращаются к серверу: при сбое клиент не создаёт тестовый аккаунт и не выдумывает код Telegram. Существующие данные локального демонстрационного режима из присланного файла не удаляются, но в рабочий серверный чат автоматически не переносятся. Профили требуют установленного серверного дополнения, а поиск пользователей, реакции, редактирование, пересылка и удаление сообщений — соответствующих серверных маршрутов; старый сервер может их не поддерживать. Переключение аккаунтов требует повторного входа. Установка PWA и офлайн-режим требуют дополнительной серверной конфигурации и файлов, не входящих в этот HTML.

Как и раньше, открытие через `file://` может приводить к Cloudflare/CORS-блокировке. Обновление HTML не изменяет установленный APK — его потребуется пересобрать. `npm test` проверяет интерфейсы с имитацией ответов API в jsdom, а не работу реального Telegram-бота или внешний вид на устройстве.
